# COD-001.7 Branch Governance

## Role

Staff Architect

## Read First

- docs/development/agent-operation-guidelines.md

## Background

The Agent OS development process now has context alignment and delivery status protocols. The next requirement is defining branch and handoff rules for multiple agents working on the same repository.

## Objective

Establish Git branch governance rules for human developers and AI agents.

## Tasks

Update:

`docs/development/agent-operation-guidelines.md`

Add:

## Branch Governance Protocol

Define:

### Branch Types

- main: stable baseline, no direct development
- feature/<name>: feature development
- agent/<agent-name>/<task>: AI agent task branches
- review/<topic>: review-only branches

### Agent Rules

Agents must:

- avoid direct changes to main
- avoid automatic push without authorization
- keep branch purpose clear
- report branch information in completion reports

### Commit Rules

Commits should describe:

- purpose
- scope
- related command ID

### Handoff Rules

Agent handoff reports must include:

- branch
- commit hash
- changed files
- next action

### Merge Rules

Define responsibility for:

- review
- approval
- merge
- release

## Constraints

- Do not modify product code.
- Only improve engineering governance documentation.

## Completion Report

Include:

- changed files
- branch
- commit hash
- push status
- remote verification status
