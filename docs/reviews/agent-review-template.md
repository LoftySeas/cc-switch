# Agent review: Subject

- **Status:** Draft
- **Date:** YYYY-MM-DD
- **Reviewer:** Agent name and model/version, if available
- **Requested by:** Name or team
- **Scope:** Files, revision, pull request, or milestone reviewed
- **Related:** Architecture, ADR, milestone, issue, or command links

## Review objective

State the questions this review answers and what it explicitly does not assess.

## Inputs and method

List documents, code revisions, commands, tests, logs, and other evidence examined.
Record material limitations and unavailable inputs.

## Summary assessment

Give a concise evidence-based conclusion. Do not present a recommendation as an
approved decision.

## Findings

### Finding 1: Short title

- **Severity:** Critical / High / Medium / Low / Informational
- **Evidence:** File and line, command output, test, or reproducible observation
- **Impact:** User, system, security, reliability, or delivery consequence
- **Recommendation:** Smallest appropriate corrective action
- **Owner:** Name or team, if assigned
- **Disposition:** Open / Accepted risk / Resolved / Deferred

Repeat the finding block as needed. Write `No findings` when applicable.

## Validation performed

| Check         | Result                | Evidence                          |
| ------------- | --------------------- | --------------------------------- |
| Example check | Pass / Fail / Not run | Command, artifact, or explanation |

## Assumptions and unresolved questions

- Assumption or question, its consequence, and the owner needed to resolve it

## Recommendation

State whether the reviewed scope is ready for its next declared stage and list any
conditions. A human approver owns the final disposition.

## Human disposition

- **Decision:** Pending / Approved / Changes requested / Risk accepted
- **Approver:** Name or role
- **Date:** YYYY-MM-DD
- **Notes:** Link to approval evidence or rationale
